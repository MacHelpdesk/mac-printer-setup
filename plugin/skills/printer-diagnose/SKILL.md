# printer-diagnose：Mac 連不到印表機時，一層一層找

印表機「印不出來」最常見的原因是 Mac 與印表機不在彼此看得到的網路位置上，而佇列的狀態仍顯示閒置，看不出來。這個 skill 先找出印表機實際在哪裡，再把佇列改過去。

**實測範圍**：下面標「已實測」的行為都在 macOS 27.3、一台 Epson 噴墨複合機（IPP）、家用兩層路由器的環境下跑過（2026-11-11）。其他廠牌、其他 macOS 版本沒有實測；遇到輸出與這裡寫的不同，把原文貼給使用者，不要硬套。

## Step 0：建立任務清單

用 TaskCreate 建立下面七個 task（subject 直接複製），一次建完。做完一個就標 completed。

要先建清單的原因：前三步都是很快的機械檢查，做完很容易直接跳到「請使用者去看印表機」，而漏掉第 5 步的掃描。來源案例就是這樣多繞了三輪。

| # | subject | 類型 |
|---|---|---|
| 1 | 列出佇列與可達性 | 機械 |
| 2 | 看本機網路位置與第二跳 | 機械 |
| 3 | 瀏覽 Bonjour | 機械 |
| 4 | 判斷印表機可能在哪一層 | **判斷** |
| 5 | ⚠️ 掃描並辨識印表機（請使用者走到印表機前必做） | **判斷** |
| 6 | 修改佇列 | 機械 |
| 7 | 驗證與回報 | 驗證 |

## 腳本位置

唯讀檢查都由 `${CLAUDE_PLUGIN_ROOT}/scripts/printer-probe.sh` 做。這個路徑讀不到時，改用載入本 skill 時顯示的 base directory 往上兩層的 `scripts/printer-probe.sh`。下文寫成 `printer-probe.sh <子命令>`。

## 行為界線

### 這個 skill 的主動連線：只有這五種，不得依性質相似類推第六種

這張表管的是照這個 skill 做事時開的連線。`printer-autoswitch` 裝的 agent 另外會定時測設定檔裡每台印表機的一個埠，那是使用者自己列的位址，不在這張表內。這個 skill 不 ping。

| # | 連線 | 什麼時候可以做 |
|---|---|---|
| 1 | 對現有佇列 URI 裡的位址測一個埠（`queues`） | 隨時 |
| 2 | 瀏覽 Bonjour（`bonjour`）、只走兩跳的 traceroute（`net`） | 隨時 |
| 3 | 掃描這台 Mac 所在的 /24（`scan`）。會對每個位址試 631 與 9100 兩個埠，再對檢查用的主機（預設閘道）試最多四個埠 | 使用者在這次對話說過，這是他自己管的網路（家裡、自己的辦公室） |
| 4 | 掃描第二跳所在的私有 /24（`scan`） | 第 3 種的條件成立，**而且**問過使用者「第二跳那台路由器也是你管的嗎」，他回答是 |
| 5 | 對一個位址送 IPP 查詢（`identify`） | 位址來自：第 3、4 種掃描的結果、現有佇列的 URI、或使用者自己給的（例如從印表機面板讀到的） |

第 4 種一定要問，不能只是告知。`net` 看到第二跳是私有位址時，分不出那是使用者自己的第二台路由器，還是電信業者或大樓的設備。只有一台路由器的家庭，第二跳常常就是電信業者的網路，掃下去就是掃別人的。

使用者沒說過網路是誰的，就問。兩個問題放在同一則訊息：

> 這是你家裡或你自己管的網路嗎？
> （`net` 顯示第二跳是私有位址時才加這一題）第二跳那台 X.Y.Z.W 也是你管的嗎？常見的情況是電信數據機後面再接一台自己的路由器，那樣兩台都是你的。

旅館、會場、學校、公司這類別人管的網路，或使用者不確定，就不掃描。這時 Step 5 只做其中不需要掃描的部分，見該步驟。

### 會改動的事：只有這五件

| 動作 | 怎麼做 |
|---|---|
| 把佇列改到新位址（`lpadmin -p … -v …`） | 符合 Step 6 的條件就做，做完回報，並附上舊 URI |
| 同步自動切換的設定檔 `~/.config/mac-printer-setup/printers.conf` | 只改被動到的那個佇列的那一行（Step 7）：佇列換了位址就改 HOST，並把 PORT 改成 631 或拿掉（Step 6 寫進去的一律是 IPP）；佇列被刪了就拿掉那一行。做完回報改了什麼 |
| 取消佇列裡等待中的工作 | 先問。佇列修好後，等待中的工作會直接印出來 |
| 刪除重複的佇列（`lpadmin -x`） | 先問。只提 `queues` 回報「共用同一個 URI」的那幾個 |
| 印測試頁 | 先問。會出紙、有聲音；本版沒有實測過從指令列印測試頁，請使用者從任何 app 印一頁 |

要問的事集中在同一則訊息一次問完。

### 不做：只有這五件

- 把 Mac 連到印表機的 Wi-Fi Direct（`DIRECT-…`）。Mac 會離開原本的網路，而且換回來之後一樣找不到印表機。
- 讀取、猜測或輸入 Wi-Fi 密碼。
- 登入路由器或印表機的管理頁改設定。
- 新增佇列。本版只實測過修改既有佇列；沒有佇列時，找到位址後請使用者在「系統設定 → 印表機與掃描器」用那個位址加入。
- 啟用被停用的佇列，或改佇列的其他設定。

## Step 1：列出佇列與可達性

```bash
printer-probe.sh queues
```

開頭兩行是預設印表機的系統層與使用者層，兩層可以不同（見〈踩過的坑〉第 5 點）。接著每個佇列一列，四欄：QUEUE、STATUS、URI、MODEL。STATUS 有四種：

| STATUS | 意思 |
|---|---|
| `reachable` | URI 裡的主機與埠現在連得到 |
| `unreachable` | URI 裡有主機，但連不到 |
| `bonjour` | URI 是 `dnssd://…`，靠 Bonjour 廣播找印表機，沒有固定位址 |
| `not-probed` | 沒有可以測的主機或埠：USB、雲端列印（例如 `epsonremote://`）、URI 裡帶帳號、IPv6 位址、不認得的協定而且 URI 沒寫埠 |

找出使用者說的那一台對應哪個佇列。有兩個以上的佇列都可能是它，而且使用者沒指明，就問是哪一台。

## Step 2：看本機網路位置與第二跳

```bash
printer-probe.sh net
```

留意有沒有 `second hop is private: A.B.C.0/24` 這一行。有的話，這台 Mac 的閘道後面還有一個私有網段。接在那個網段的印表機，Bonjour 廣播到不了這台 Mac，但用位址連得到（已實測）。那個網段是不是使用者的，這個指令分不出來，要照〈行為界線〉第 4 種去問。

## Step 3：瀏覽 Bonjour

```bash
printer-probe.sh bonjour
```

列出這個網段上正在廣播的印表機。四種服務類型各等 4 秒，總共約 16 秒。

## Step 4：判斷印表機可能在哪一層

照目標佇列的狀態找到對應的一列。表格涵蓋所有情況，沒有「其他」。

| 目標佇列 | Step 2、3 | 判斷 | 下一步 |
|---|---|---|---|
| `reachable` | 不論 | 網路是通的 | 不是連線問題。回報這一點後停止，本 skill 不處理佇列暫停、驅動、耗材 |
| `bonjour` | Bonjour 列得到這台 | 廣播收得到 | 同上。例外：使用者是從 `printer-autoswitch` 過來、要把它改成固定位址的佇列，見表格下方 |
| `bonjour` | Bonjour 找不到 | 印表機沒開、沒連上網路，或在別的網段（包括第二跳那一段） | Step 5 |
| `unreachable`，URI 的主機是位址，而且不在本機網段、也不在第二跳的網段 | 不論 | 這個佇列多半屬於別的地點（例如辦公室的印表機）；換過路由器、網段變了也會這樣 | 問使用者現在要用的是哪一台、它在哪裡。他說就是這一台、就在這裡 → Step 5；他說是另一台 → 用那一台的佇列從這張表重新查 |
| `unreachable`，其他情況（位址在本機或第二跳的網段，或主機是名稱） | 不論 | 印表機的位址可能換了（DHCP），或不在線上 | Step 5 |
| `not-probed` | 不論 | 不是網路印表機，或本 skill 測不了 | 說明沒涵蓋後停止 |
| 沒有對應的佇列 | 不論 | 還沒加入這台印表機 | Step 5 找位址，再請使用者用那個位址在系統設定加入（本 skill 不新增佇列） |

**從 `printer-autoswitch` 過來、要把正常的 Bonjour 佇列改成固定位址**：先告訴使用者代價（固定位址在 DHCP 換位址後要再改一次；Bonjour 佇列沒有這個問題），他仍要改，就照 Step 5 找出位址，再做 Step 6。

## Step 5：⚠️ 掃描並辨識印表機

**這是最容易做錯的一步。在請使用者走到印表機前面看面板之前，下面四項裡可以做的都要做過。** 這個 skill 的來源案例裡，第三項沒做就請使用者去設定印表機的 Wi-Fi，而印表機其實一直用網路線接在第二跳的網段，3.7 秒的掃描就找得到。

每一項先看〈行為界線〉的條件。條件不成立的項目跳過，並在回報中寫明跳過的原因；不要因為這一步標了「必做」就掃不該掃的網路。

1. 掃本機網段（第 3 種的條件）。`A.B.C` 是 Step 2 本機位址的前三段；`net` 列出不只一個介面時，用與預設閘道同一個 /24 的那一個。第二個參數是預設閘道：
   ```bash
   printer-probe.sh scan A.B.C <預設閘道>
   ```
2. 讀最後一行 `check:`。寫著 `answers on port …` 才代表掃描到得了那個網段。寫著 `did not answer` 時，空結果不能當成「沒有印表機」，照實回報「掃描到不了，無法判斷」。輸出是 `refusing to scan …` 而沒有 `check:` 行時，表示那個網段不是私有網段（腳本不掃），這一項跳過並照實回報。
3. Step 2 有 `second hop is private` 時，照第 4 種的條件問過、使用者回答是，才掃。第二個參數用 Step 2 的 second hop：
   ```bash
   printer-probe.sh scan X.Y.Z <second hop>
   ```
4. 看附近有沒有印表機的 Wi-Fi Direct。這一項不開任何連線，隨時可以做：
   ```bash
   printer-probe.sh wifi-direct
   ```
   看到 `DIRECT-…` 只代表那台印表機開著、在附近。它可以同時用網路線接在區域網路上（已實測），所以**不能據此判斷它沒連上網路**。

掃到開著 631 的主機，就逐一辨識：

```bash
printer-probe.sh identify <位址>
```

只開著 9100 的主機不說 IPP，`identify` 會回 `no IPP answer`，這不代表它不是印表機；這種主機請使用者指認。使用者指認之後到此為止：回報它的位址，跳過 Step 6。Step 6 只會寫 IPP 的 URI，本版不替只開 9100 的主機改佇列。

**怎麼對出是哪一台**：

- 原佇列的 URI 是 `dnssd://…?uuid=<UUID>` 時，`identify` 的 `printer-uuid` 與它相同，就是同一台（已實測），不必再問。
- 沒有 UUID 可比時，拿 `identify` 的 `printer-make-and-model` 對 Step 1 的 MODEL 欄。對的是廠牌與型號名稱，MODEL 欄後面的驅動字樣（例如 `-AirPrint`）不算。型號對上之後，**一律請使用者確認**「在 <位址> 找到一台 <型號>，是你要用的那台嗎」，不論找到一台或多台。
- 沒有對應的佇列時（Step 4 最後一列），沒有東西可以比。把 `identify` 的型號與位址告訴使用者，請他確認，再請他自己用那個位址在系統設定加入。跳過 Step 6；Step 7 的第一項與設定檔那一項不適用，其餘照做。

可以做的項目都做過仍找不到，或前三項因為條件不成立而跳過，才請使用者看印表機：電源有沒有開；面板的網路狀態顯示它連的是哪個網路、位址是多少。使用者回報位址之後，直接 `identify <那個位址>`（第 5 種），對上了就到 Step 6。`identify` 回 `no IPP answer` 時，只回報「那個位址從這台 Mac 沒有回應 IPP」，並把使用者從面板讀到的網路名稱與位址一起附上；不要下「印表機與 Mac 不在互通的網路上」這種結論，這個指令分不出是連不到還是對方不說 IPP。

## Step 6：修改佇列

條件（擇一）：UUID 相同；或型號相符，而且使用者確認了這一台。

先看這個佇列有沒有等待中的工作：

```bash
lpstat -o <佇列名稱>
```

沒有輸出就是沒有（已實測）。有的話，佇列一修好它們就會印出來。告訴使用者有幾件，問要保留還是取消；要取消時，請他在列印佇列視窗取消，或經他同意後執行 `cancel -a <佇列名稱>`（本版未實測）。

再記下舊 URI（Step 1 的輸出），然後改：

```bash
lpadmin -p <佇列名稱> -v ipp://<位址>/ipp/print
```

這個指令只換連線位址，驅動與預設選項沿用（已實測）。不要加 `-E`：那會順便啟用佇列並開始接受工作，不在這個 skill 會改動的五件事裡。佇列名稱用 Step 1 的 QUEUE 欄，不要從 `lpstat -p` 的文字裡抄（見〈踩過的坑〉第 4 點）。

## Step 7：驗證與回報

全部通過才算完成：

- [ ] `printer-probe.sh queues` 裡，目標佇列是 `reachable`，URI 是新位址。
- [ ] 取消工作、刪佇列、印測試頁，有做的都是使用者同意過的。
- [ ] 讀 `~/.config/mac-printer-setup/printers.conf`（不存在就跳過）。裡面有這個佇列的話，把它的 HOST 改成新位址，PORT 改成 631 或拿掉；佇列被刪掉的話，把那一行拿掉。否則自動切換會繼續測舊位址，而且不會出聲。
- [ ] 回報裡有舊 URI（要改回去時用）。
- [ ] 回報裡有下面這段位址會變的提醒。
- [ ] 回報裡寫明 Step 5 哪些項目做了、哪些因為條件不成立而跳過。

**位址會變的提醒（改成固定位址的佇列都要講）**：這個位址是路由器用 DHCP 分配的，日後可能換，到時佇列又會連不到。兩個一勞永逸的做法，都要使用者自己動手：

1. 在分配這個位址的路由器上，把位址綁定給這台印表機（DHCP 保留）。
2. 把印表機改接到 Mac 所在的那台路由器。兩者同網段之後 Bonjour 找得到它，位址怎麼變都不影響；這種接法下，佇列可以改回 Bonjour 的 URI。

回報要短：印表機在哪裡找到的、佇列從哪個 URI 改成哪個、還有什麼要使用者決定（重複佇列刪不刪、要不要印測試頁）。

使用者之後想讓預設印表機跟著地點換，用 `printer-autoswitch`。

## 踩過的坑

都來自實測（macOS 27.3，2026-11-11）。

1. **Bonjour 過不了路由器，位址連線過得了。** 印表機接在第二跳的網段時，`dnssd://` 的佇列失效，改成 `ipp://<位址>/…` 就能印。
2. **看得到 Wi-Fi Direct 不代表印表機沒連上區域網路。** 見 Step 5 第 4 項。
3. **空的掃描結果要先驗掃描方法。** 受限的執行環境（例如沙盒）裡，`arp -an` 可能完全沒有輸出，連預設閘道都不在裡面。所以不用 ARP 表下結論；`scan` 最後的 `check:` 行就是用來分辨「真的沒有」和「掃不到」。
4. **`lpstat` 的文字跟著系統語言走，`LC_ALL=C` 也改不了。** 中文系統下 `lpstat -p` 印出「印表機NAME閒置」，中間沒有空格，很容易把「印表機」三個字當成名稱的一部分。名稱用 `lpstat -e`，URI 與型號用 `lpoptions -p <名稱>`；`printer-probe.sh queues` 就是這樣做的。
5. **預設印表機有兩層。** 系統層用 `lpadmin -d` 設，使用者層在 `~/.cups/lpoptions`（`lpoptions -d` 寫入）。`lpstat -d` 有使用者層時只回報使用者層，所以單用 `lpadmin -d` 改完，`lpstat -d` 可能看起來沒變。
6. **舊佇列的位址落在本機網段以外的私有網段，是線索。** 它表示以前有一個走得到的私有網段，多半就是第二跳那一段。用 `printer-probe.sh net` 確認第二跳，不要把那個佇列當成無關的舊資料。
7. **舊佇列常常就是同一台印表機的舊位址。** 一個 `unreachable` 的佇列，MODEL 與現在找到的印表機相同、位址在同一個網段，多半是 DHCP 換位址之前留下的。這也是 Step 7 那段提醒的實例。
